# Working with Dials

Rules for AI agents and people building with Dials, an AI-first CSS framework. Copy the rules section below into a project's own `AGENTS.md` or `CLAUDE.md`.

## Files

| File | What it is |
|---|---|
| `dials.css` | Colour, type and space in one file, with the fallback for older browsers. The Hi-Fi house theme is its default |
| `dials-colour.css`, `dials-scale.css` | The colour half and the type-and-space half on their own |
| `dials-base.css` | Optional: plain HTML elements styled from the tokens, at zero specificity |
| `themes/*.css` | Ready-made themes: dial settings only, loaded after `dials.css` |
| `docs/tokens.md`, `docs/tokens.json` | The complete public token reference: every dial and token, its default and what it's for |

Every file above is generated by `build.py`; never edit them. In this repository the sources are `src/*.css`, `presets/` and `themes.json`.

The full token list is in [docs/tokens.md](docs/tokens.md) (and [docs/tokens.json](docs/tokens.json) for tools). Anything prefixed `--dl-` is internal plumbing: never use or set it.

## Dials: colour, type and space

- Load `dials.css` (and optionally `dials-base.css`), then a theme if any, then your own stylesheet. Never edit `dials*.css` or a theme file: your dials and your components go in your own file, loaded after them.
- Dials are the only typed values. Set them in your own file at `:root`, or on a `[data-dials]` element to re-theme part of a page: `<div data-dials style="--brand: hsl(270 60% 50%)">`. Never set a dial on any other selector, and never set a derived token.
- Colour dials are `--brand`, `--accent`, `--success`, `--warning`, `--danger`, `--info` and `--grey`, preferably in HSL (`--brand: hsl(37 90% 51%);`), though any CSS colour works. To change the look, change a dial. Never write a hex, `rgb()`, `hsl()` or named colour anywhere else.
- Components use only the public tokens in `docs/tokens.md`: `--surface*`, `--text*`, `--link*`, `--border*`, `--focus`, `--selection`, `--shadow-*`, the gradient tokens, and `--solid` / `--on-solid` / `--soft` / `--on-soft` / `--line`. Never use a `--dl-*` property.
- A `solid` or `soft` background always sets its matching `on-` colour in the same rule.
- `.is-brand|accent|neutral|success|warning|danger|info` only switches which group `--solid`, `--on-solid`, `--soft`, `--on-soft` and `--line` point at. Components read those five tokens; never style a component per group class.
- Set the colour scheme on purpose. `dials.css` sets `:root { color-scheme: light dark; }`, which follows the visitor; to force one, write `:root { color-scheme: light; }` (or `dark`) in your own file. A dark band is `class="is-dark"` on the section. Never a second set of colours.
- A new shade is derived from a token with `color-mix(in oklab, …)` or `oklch(from var(--token) …)`, declared once as a custom property in your own file with a comment, never inline.
- Every font size is a `--size-*`, every gap and padding a `--space-*` (or a pair like `--space-s-l` for a gap that should grow faster), every corner a `--radius-*`, every border and outline width a `--border-width-*`, every face `--font-body`, `--font-heading` or `--font-mono`. Never write a length in px, rem or em except through these tokens. Line heights and font weights are unitless numbers.
- To change sizing, change a dial: `--size-min`/`--size-max`, `--ratio-min`/`--ratio-max`, `--space-density`, `--radius-base`. Never retune one step by hand.
- Text pairs keep 4.5:1, focus rings and control borders 3:1, in light and dark. Run the contrast check (`node checks/contrast.mjs`) before calling it done.
- With `dials-base.css`, native elements (headings, links, tables, form fields, `<button>`) are already styled. Don't restyle them per page; build components on top from the tokens.

## Notes for this repository

- Change `src/*.css`, `presets/*/*.css` or `themes.json`, then run `python3 build.py`. `python3 build.py --check` fails if anything generated is stale.
- `src/fallback.css` is the hand-edited fallback for browsers with `color-mix()` but without relative colour: it re-derives every colour token from the dials with `color-mix()` alone, and must never set a dial or use relative colour, `light-dark()` or `calc()` (`build.py` refuses). Add any new colour token there too.
- `src/fallback-flat.css`, the last resort for browsers without `color-mix()`, is generated by `node tools/fallback.mjs` from the built `dials.css`; after changing `src/colour.css`, run `build.py`, then `tools/fallback.mjs`, then `build.py` again (`build.py --check` fails until you do).
- `dials.css`'s defaults must match the Hi-Fi presets (`presets/colour/hi-fi.css`, `presets/type/hi-fi.css`, `presets/space/machined.css`); `build.py` refuses to build if they differ.
- Checks: `node checks/contrast.mjs` (themes and random extreme dials, Chromium and Firefox; `--fallback` for the fallback), `node checks/scoping.mjs`, `node checks/playground.mjs`. They need Playwright 1.62.1 (`npm install`, `npx playwright install chromium firefox`).
