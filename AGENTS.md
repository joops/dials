# Working with Dials

Rules for AI agents and people building with Dials, an AI-first CSS framework. Copy the rules block below into a project's own `AGENTS.md` or `CLAUDE.md`; it doesn't change between minor versions unless the CHANGELOG says so.

## Files

| File | What it is |
|---|---|
| `dials.css` | Colour, type and space in one file, with the fallback for older browsers. The Hi-Fi house theme is its default |
| `dials-colour.css`, `dials-scale.css` | The colour half and the type-and-space half on their own |
| `dials-base.css` | Optional: plain HTML elements styled from the tokens, at zero specificity |
| `themes/*.css` | Ready-made themes: dial settings only, loaded after `dials.css` |
| `docs/tokens.md`, `docs/tokens.json` | The complete public token reference: every dial, token and class, its default and what it's for, and the documented patterns (gradients among them) |

Every file above is generated by `build.py`; never edit them. In this repository the sources are `src/*.css`, `src/patterns.md`, `presets/` and `themes.json`.

The full token list is in [docs/tokens.md](docs/tokens.md) (and [docs/tokens.json](docs/tokens.json) for tools). Anything prefixed `--dl-` is internal plumbing: never use or set it.

## Rules

Copy the rules block below into your project's own `AGENTS.md` or `CLAUDE.md` as it is. It names no dial, token or class: it says how to use Dials, and points at the token reference of the version you use for the names. It doesn't change between minor versions unless the CHANGELOG says so.

## Dials: colour, type and space

- **Look every name up in the version you use.** Every dial, token and class, with its default and what it's for, is in that version's `docs/tokens.md`. Use those names, never ones remembered from another version. For a pinned or copied `dials.css`, the version is in its first line (`/*! Dials vX.Y.Z | …`) and its reference is at `https://github.com/joops/dials/blob/vX.Y.Z/docs/tokens.md`.
- Load `dials.css` (and optionally `dials-base.css`), then a theme if any, then your own stylesheet. Never edit a Dials file or a theme file: your dials and your components go in your own file, loaded after them.
- Dials are the only typed values. Set them in your own file at `:root`, or on a `[data-dials]` element to re-theme part of a page. Never set a dial on any other selector, and never set a token Dials works out.
- To change the look, change a dial. Never retune one shade, size or step by hand.
- Colours are typed only as colour dials, preferably in HSL (`hsl(37 90% 51%)`), though any CSS colour works. Never write a hex, `rgb()`, `hsl()` or named colour anywhere else.
- Components use only the public tokens in the reference. Anything prefixed `--dl-` is internal plumbing: never use or set it.
- A solid or soft background always sets its matching on- colour in the same rule.
- Components read the ungrouped roles (solid, on-solid, soft, on-soft, line). A group class only switches which group those roles point at; never style a component per group class.
- Coloured text uses an on- colour; coloured borders, icons and large text use a line. Never put a solid or soft colour on text.
- Set the colour scheme on purpose. Dials follows the visitor's light or dark setting; to force one, set `color-scheme` on `:root` in your own file. A dark section is the dark band class on that section, never a second set of colours.
- A new shade is derived from a token with `color-mix(in oklab, …)` or relative colour (`oklch(from … )`), declared once as a custom property in your own file with a comment, never inline.
- Every font size, gap and padding, corner, border and outline width and face comes from its scale in the reference. Never write a length in px, rem or em except through those tokens. Line heights and font weights are unitless numbers.
- Dials has a token only where it works something out or guarantees something. Anything you can build from tokens (a gradient, a wash, a hover shade) is a pattern: build it in your own file from tokens, following the patterns in the reference. A gradient that runs from a solid to anything else is decoration only: no text on it.
- Text keeps 4.5:1 against its background; large text (24px, or 18.66px bold, and up), icons, focus rings and control borders keep 3:1, in light and dark. Dials' tokens hold these on its own surfaces and tints; check anything you compose yourself before calling it done.
- With `dials-base.css`, native elements (headings, links, tables, form fields, buttons) are already styled. Don't restyle them per page; build components on top from the tokens.

## Notes for this repository

- Change `src/*.css`, `src/patterns.md`, `presets/*/*.css` or `themes.json`, then run `python3 build.py`. `python3 build.py --check` fails if anything generated is stale. `src/patterns.md` is appended to `docs/tokens.md`.
- The token rule: add a token only when Dials computes or guarantees something (a colour worked out from the dials, a contrast it holds). Anything a site can build from existing tokens is a documented pattern in `src/patterns.md`, not a token.
- The rules block stays version-agnostic: no dial, token or class names, except where a rule can't be stated without one (today: `dials.css`, `dials-base.css`, `docs/tokens.md`, `[data-dials]`, the `--dl-` prefix). Names live in `docs/tokens.md`. If a release has to change the rules block, say so in the CHANGELOG.
- Renaming a dial or token: keep the old name working for at least one minor release (a `var(--old, var(--new))` read for a dial, a `var()` alias for a token or class, in both `src/colour.css` and `src/fallback.css`), list it in `DEPRECATED_DIALS` in `build.py` or mark its comment "deprecated", and say so in the CHANGELOG. `--accent` is the current example.
- Coloured text and lines (`--*-on-soft`, `--*-line`, `--link-hover`) move a colour only as far as their contrast target needs; the formula is explained in `src/colour.css` above the groups. They're generated per group: keep the six coloured groups' formulas identical apart from their names.
- `src/fallback.css` is the hand-edited fallback for browsers with `color-mix()` but without relative colour: it re-derives every colour token from the dials with `color-mix()` alone, and must never set a dial or use relative colour, `light-dark()` or `calc()` (`build.py` refuses). Add any new colour token there too.
- `src/fallback-flat.css`, the last resort for browsers without `color-mix()`, is generated by `node tools/fallback.mjs` from the built `dials.css`; after changing `src/colour.css`, run `build.py`, then `tools/fallback.mjs`, then `build.py` again (`build.py --check` fails until you do).
- `dials.css`'s defaults must match the Hi-Fi presets (`presets/colour/hi-fi.css`, `presets/type/hi-fi.css`, `presets/space/machined.css`); `build.py` refuses to build if they differ.
- Checks: `node checks/contrast.mjs` (themes and random extreme dials, Chromium and Firefox; `--fallback` for the fallback; it also fails a coloured text or line that over-shoots its target), `node checks/scoping.mjs`, `node checks/playground.mjs`. A contrast or behaviour you add needs a pairing or assertion there. They need Playwright 1.62.1 (`npm install`, `npx playwright install chromium firefox`).
