# Checks

Every check serves the project over a local HTTP server and drives Chromium and Firefox with Playwright 1.62.1. Each exits 1 on failure.

```sh
npm install                                   # Playwright 1.62.1, from package.json
npx playwright install chromium firefox
node checks/contrast.mjs                      # [--fallback] [--browser=firefox] [--random=40] [--seed=1] [--verbose]
node checks/scoping.mjs
node checks/type.mjs                          # [--browser=firefox] [--random=30] [--seed=1] [--verbose]
node checks/sameness.mjs                      # [--browser=firefox] [--random=40] [--seed=1] [--verbose]
node checks/playground.mjs
```

- `contrast.mjs` loads the built `dials.css` and `dials-base.css`, alone, with each `themes/*.css`, and with 40 seeded sets of extreme random dials (yellows, near-white, near-black, very low chroma, saturated, with random balance, tint and white-text settings). In a light page, a dark page and an `.is-dark` band, it measures: every text token (`--text-strong`, `--text`, `--text-muted`, `--text-quiet`, `--link`) on `--surface`, `--surface-raised` and `--surface-lowered` at 4.5:1, and `--link-hover` there at 7:1 (4.5:1 in the fallback); each group's on-solid on solid at 4.5:1; its on-soft on its soft tint and on all three surfaces at 4.5:1; its line on its soft tint and the surfaces at 3:1 (not neutral's, which is the decorative `--border`); `--text` on every soft tint and on a wash between two of them (the pattern in `docs/tokens.md`) at 4.5:1; `--focus` and `--border-strong` on surface and raised at 3:1. In normal mode it also fails a coloured text or line that over-shoots: when a group's on-soft or line differs from the colour it starts from (the fill clipped to sRGB, or the dial), its worst ratio on those backgrounds must be within 0.35 of its target (the 0.1 headroom plus 0.25 for 8-bit painting). And it checks the field numbers from two real sites: `#007a70` on white keeps its colour, `#d04a04` lands between 4.5 and 4.85:1 with its hue, and teal text on a navy `.is-dark` band lands between 4.5 and 5.3:1. It also fails any of those foregrounds that is translucent, and checks that on-solid text is opaque on a translucent fill. With `--fallback` it measures the same pairings on the fallback for older browsers, emulated as below, in a light page and an `.is-dark` band (the fallback has no dark page), and reports the random dial sets' pass rate.
- `exceptions.json` lists failures the contrast check tolerates, each with a reason. Normal mode has none, and no theme ever gets one. The fallback has one per colour group, for random dial sets only: its on-solid text is a fixed white or black, which extreme fills can defeat.
- `scoping.mjs` checks that `[data-dials]` re-derives colour and space, that a site setting the deprecated `--accent` (at `:root` or in a scope) still gets its secondary colour, with `--accent-*` and `.is-accent` following, `--grey` changes paper and ink, an exact `--paper-light` wins, base rules lose to a later zero-specificity rule even on `:hover` and `:focus-visible`, that the fallback (emulated) follows a site's purple brand, exact paper and `--accent`, re-derives a `[data-dials]` scope, keeps `.is-danger` winning and darkens an `.is-dark` band, and that the last resort (emulated) is valid and flat.
- `sameness.mjs` holds the colour to v0.4.0's (`fixtures/v0.4.0/dials.css`, verbatim, never edit it): it loads that file and the built `dials.css` on two pages with the same dials (none, each theme, each theme with exact papers, four exact papers including a dark navy `--paper-dark`, and 40 seeded extreme random dial sets, every fourth with random exact papers) and fails any colour token in `docs/tokens.json`, for any group, that paints more than 1/255 per channel away from v0.4.0's, in a light page, a dark page and an `.is-dark` band. It guards 0.4.1's rewrite of the soft tints (and paper, ink and fills) into OKLab a and b, which is the same colour by construction. When a release changes a colour on purpose, move the fixture to that release in the same change and say so in the CHANGELOG.
- `type.mjs` guards type. It renders every element `dials-base.css` styles (and the same elements inside a parent with its own letter spacing, leading and weight) with `--leading-body` set to its default and with nothing set, at 360px and 1280px, and fails any difference in any computed property (custom properties aside) or in any element's box (x, y, width, height): with no theme, with each theme (keeping the theme's own leading), after a zero-specificity reset loaded before `dials-base.css`, and in the playground's scoped demo under page rules it outranks. Against v0.2.0's files (`fixtures/v0.2.0/`, verbatim), it compares the Dials theme with v0.2.0's Hi-Fi and allows only line height, block margins and the sizes they move. It checks that `dials.css` alone sets no type on any element. Across 30 seeded random dial sets (scale and leading) and three widths, it measures `--leading` at every step, every half step and past both ends: exact at body size and on the reference formula (body's gap between lines at every larger size, the body ratio below, never under 1.05), worked out from the sizes the browser gave (0.02px in Chromium; in Firefox 0.03px plus the gap × 1/64px, since it rounds font sizes). And with `dials-base.css`: a component that sets only its font size gets its own leading, paragraphs are one body line apart and follow the leading, letter spacing and weights are left alone, a `[data-dials]` scope applies its leading inside it only, and `.is-typeset` opts in.
- `playground.mjs` loads `site/` and checks there are no console errors, and that every preset, theme, Randomise, the scheme switch, the format switch and both export modes work. For type: the Leading slider shows its default until moved, opens up the preview panes, the article, the base demo and the page's own headings (body text exactly, larger text less), keeps paragraphs one body line apart, and a preset puts it back; themes set or clear the leading (Default none, Dials 1.6); Randomise keeps it between 1.35 and 1.8; the page's own text follows the type scale.
- `lib.mjs` holds the shared server and browser launcher, the seeded random dial sets `contrast.mjs` and `sameness.mjs` share, and `emulateFallback`, which emulates an older browser on the text of `dials.css`: it turns the fallback's `@supports` on and breaks relative colour, `light-dark()` and gradient interpolation (and `color-mix()`, for the last resort) everywhere else, so anything that relies on them fails as it would there. Both checks print what it patched. If Playwright's own Firefox build isn't installed, it uses `DIALS_FIREFOX` or another Firefox build in the Playwright cache.
