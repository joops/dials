Mixes a random colour, type and space preset into a new combination. It doesn't choose one of the themes: press it again for another.

Dial in kick-ass sites and web apps

Dials is an AI-first CSS framework, a token-based system designed to produce a huge diversity of looks from only a few dials: seven colours in HSL, a handful of type and space settings, three fonts and a corner radius. Everything else is derived from these values using plain CSS, live in the browser: every surface, text level, border and colour group, in light and dark, with contrast checked as you go; and every text and space size, fluid from phone to desktop with no breakpoints. Let's jam!

Other calculators and systems generate colours, type and space once, as fixed values, which limits what a theme can change on a live site. Dials derives all three dynamically from the values you define, so a theme can change the whole look of a page or app: its colours, type scale, spacing, faces and corners.

AI-first means an agent gets a short set of rules and a small set of tokens, so it can build a theme quickly and stay within the guidelines, and you can riff on it in real time to dial in the perfect look for your new project.

1 · Dials

Seven colours in HSL. One switch evens out their lightness so they carry equal weight.

2 · Derived

Surfaces, text, lines, focus and shadows, blended from paper and ink with color-mix() or relative colour.

3 · Groups

Brand, secondary, neutral and four status colours each get the same five roles. .is-danger points a component at one.

4 · Type and space

Body size and ratio at narrow and wide screens give fluid type and space, with no breakpoints. Three fonts, a density, a radius.

5 · Base (optional)

Plain HTML styled from the tokens at zero specificity: text, tables, forms and real buttons, no classes needed.

Tune it

Presets

Colour dials are preferably written in HSL, the easiest format to reason about and to tell an agent "the same blue, a bit darker". Click a swatch to choose a colour; the pop-up can switch the format to hex, RGB or OKLCH for the text boxes and the CSS below.

On: every button and badge gets the same lightness, so no colour shouts louder than another. Off: each colour exactly as set, for a brand that must match. Either way, button text flips between white and black to keep its contrast.

More: exact paper and ink, dark lift, tints, text contrast, button text

The grey dial tints paper (near-white) and ink (near-black) for you. Tick one to set it exactly instead.

Soft tints are the colour blended into the paper. Strength sets how much; vividness makes them more saturated, for crisp pastels rather than greyed washes.

Strengthens body, muted and quiet text. Raise it when paper and ink sit close together, as many editor themes do, until the contrast table passes.

Button text is white or black, whichever contrasts more with the fill: the switch is at luminance 0.179, where the two are equal. Raise it a little to keep white text on a fill just over the line. Dials holds it between 0.175 and 0.18333, where both white and black still pass.

Presets

Leading, tracking and weight

These start unset, so dials-base.css keeps the type it has always had. Move one to set it; × unsets it. Leading and tracking are set at two ends, body text and the top of the scale (--size-8), and every size in between slides along a curve: watch the scale beside the article. Tracking dials are in em, and any you leave unset count as shown.

Body size and ratio are set at the narrowest and widest screens, and every size runs in a straight line between them; the screen range is shared with space. A bigger ratio gives more drama between headings and body text: 1.2 is a minor third, 1.333 a perfect fourth, 1.618 the golden ratio. Faces load from Google Fonts: choose one, or type any family name. The mono face is for code; its list holds every monospace family on Google Fonts.

Presets

By default --space-s equals body text size, so spacing keeps its rhythm with the text: Utopia's approach. Untick it to set the space base on its own, for tight text in a roomy layout or the reverse. Density scales every space size and pair together; radius sets the corners.

Type and space

Studio notes

Get a better mix in a small room

Treat the corners, sit in the sweet spot and turn it down. That's most of it.

Body text sits at --size-0. The gap between paragraphs is --space-s, headings get --space-l above them and this card's padding is --space-l, so the rhythm tightens on a phone and opens up on a desktop.

What you need

A pair of near-field monitors, a decent interface and one set of headphones you know well enough to check against.

Plain HTML with dials-base.css

An optional third file. It styles ordinary elements from the Dials tokens, so a page with no classes already looks right: text, links, lists, tables, form fields and real buttons. Every rule has zero specificity, so anything your site writes wins. It has no component classes; a link that should look like a button is your own component, built from --solid and --on-solid.

Contrast

Worked out live from the colours above, for every pairing the system promises. Text needs 4.5:1 (WCAG AA); focus rings and control borders need 3:1. The same pairings are checked in CI against the shipped files, every theme and 40 sets of extreme random dials.

Every token

marks a dial: a value you set. Every other token is worked out from the dials, so use it but never set it. Swatch halves: light, then dark. Every group follows the same pattern, so a yellow warning and a deep blue info both pass without special cases.

Use it

  
    
    
  1. Load Dials: dials.css, then the Google Fonts link for your faces (each theme file names its own). No build step, no dependencies.
    2. 
    
  2. Set your dials in your own stylesheet, loaded after dials.css: copy the theme file above, or start from one in themes/. Colour dials are preferably HSL (--brand: hsl(37 90% 51%);); any CSS colour works, so a brand hex can go straight in. Leave --balance at 0 if the brand colours must match exactly.
    3. 
    
  3. Choose the scheme: dials.css sets color-scheme: light dark, so pages follow the visitor's setting. Force one with :root { color-scheme: light; } (or dark) in your own file, and mark any dark band with class="is-dark".
    4. 
    
  4. Build components from the tokens, and point them at a colour group with a class: <button class="btn is-danger"> with .btn { background: var(--solid); color: var(--on-solid); }.
    5. 
    
  5. Re-theme part of a page with a scope: dials set on a [data-dials] element re-derive every token inside it, as in <aside data-dials style="--brand: hsl(270 60% 50%); --space-density: .8">.
    6. 
    
  6. Optionally add dials-base.css so plain HTML elements, form fields and real buttons are styled from the tokens with no classes. It has zero specificity, so your own rules always win.
    7. 
    
  7. Size everything from the scale: --size-* for every text size, --space-* for every gap, a pair such as --space-s-l where a gap should grow more than the text does, --radius-* for corners and --border-width-* for borders. It's Utopia's method, so Utopia's guides apply; there's just no calculator step.
    8. 
    
  8. Give your agents the rules below and run the contrast check in CI.
    9. 
  

  
Needs color-mix(), light-dark() and relative colour: Chrome and Edge 123+, Safari 18+, Firefox 128+. Older browsers get a built-in fallback: with color-mix() (Safari 16.2+, so iOS 16 and 17, Chrome 111+, Firefox 113+) it follows your dials in a light page, with dark bands; before that, the Hi-Fi theme as flat colours. Don't register these properties with @property: they must work out their colour where they're used, which is what makes dark bands work.

Inspired by Utopia for type and space, and by web.dev's Baseline colour themes, Web Awesome and Radix Themes for colour.

  
Colour ideas also come from web.dev (globals in light-dark()) and Web Awesome (the fill, border and "on" roles, which Dials calls solid, soft and line, and the hover fragment). Two tricks keep contrast without per-colour tuning: button text is white or black, whichever contrasts more, worked out from the fill's luminance with color(from … srgb-linear r g b), and coloured text and lines keep their colour, moved only as far as their contrast needs: their linear-light RGB is scaled, darker in light and lighter in dark, which keeps hue and saturation.
